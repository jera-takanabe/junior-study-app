# 検討・検証メモ

2026年11月17日

確定した仕様は [設計正本](design.md) を参照する。このメモは、採用理由、実機検証、費用・工数の前提を記録する。

## 採用理由と残っている判断

| 論点 | 現時点の結論 |
|---|---|
| ChatGPTのみか、専用アプリか | 専用アプリを採用。教材・認識結果・採点基準・履歴のどこでずれたかを確認できる構成にする。ChatGPTでの練習は、採点基準や解説の事前確認に使える。 |
| AWSでの構成 | API Gateway＋Lambda＋DynamoDBを初版の前提とする。家族利用を想定し、ECS＋RDSなどの常時稼働構成に比べ、固定費と保守作業を抑えやすい。 |
| Webフレームワークと配備 | Flask＋Jinja。CognitoとDynamoDBを使い、サーバー生成の画面と学習APIを一つのデプロイにまとめる。 |
| 通常の音声回答 | OpenAIの gpt-transcribe を第一候補にする。PCとスマホで同じモデルを使える。ブラウザ内蔵の音声認識との精度差は、短答や英語の実際の発話で確認する。 |
| 英語の発音評価 | Azure Speech Pronunciation Assessmentを候補として試す。文字起こしが right でも、最初の音が適切だったかは音声を評価して確かめる。 |

## 実機・採点の検証

| 順序 | 試すこと | 記録すること |
|---|---|---|
| 1. スマホの音声操作 | 開始操作の後、問題と選択肢の読み上げ、録音、回答、結果、次問を画面に触れず数問続ける。 | 端末・OS・ブラウザ、何問続いたか、録音や再開が止まる場面。画面ロック中の動作は別途確認する。 |
| 2. 文字起こしと発音 | 「2番」「0.5倍」、英語の単語・短文を実機で試す。発音は人が聞いて気づいた点と比較する。 | 発話、認識文字列、確定した判定。発音評価では、指摘した単語・音素と人の評価が合うか。 |
| 3. 採点 | 実教材10問・答案30例程度を用意。表記ゆれ、正しい言い換え、ぎこちない日本語、部分正解、似ている誤答を入れる。先に人が期待判定と理由を付け、文字と音声を分けて試す。 | 全体の一致率に加え、正答を△・×にした件数と、誤答を○にした件数を記録する。繰り返しずれる種類は、基準や処理を見直すまで自動確定を保留する。 |
| 4. 端末間の履歴 | PCで解き、スマホで同じ練習枠の履歴を見る。別の練習枠にも切り替える。 | 保存結果、練習枠の分離、同じ回答を再送した場合の重複有無。 |

2026年11月19日にiPad ProのSafariで音声操作の先行実機検証を実施した。結果は以下に記録する。文字起こし精度、発音評価、採点精度の実測はまだ行っていない。

## 音声操作・先行実機検証（2026年11月19日）

- 検証ページ：[`prototypes/voice/index.html`](../prototypes/voice/index.html)
- 機器：iPad Pro / iPadOS 26.7.3 / Safari
- 目的：一度「音声練習を開始」を押した後、読み上げ → 発話録音 → 次問を、各問の画面操作なしで3問続ける。
- 検証範囲：ブラウザの読み上げとMediaRecorderによる録音、および自動進行。**文字起こし、採点、サーバー送信、画面ロック時の動作は未検証**。

| 確認項目 | 結果・備考 |
|---|---|
| 当初の第1問読み上げ | 失敗。ステータス「第1問：読み上げ中」で音声が聞こえず、30秒後に「読み上げ完了を検出できませんでした」と表示。 |
| 読み上げ単独テスト | 成功。「読み上げテスト」ボタンで音声が聞こえ、「正常終了」と表示。 |
| 処理順序の修正 | 開始ボタン押下直後に第1問の読み上げを開始し、その後マイク許可を要求する構造に変更。 |
| 修正後の第1問読み上げ | 成功。読み上げ後にマイクアクセス許可のダイアログを確認。 |
| 連続自動進行 | 成功。マイクを許可した後、画面に触れず3問目まで進行したとの実機報告。 |
| 第1問の録音 | 「2番」が明瞭に聞こえた。 |
| 第2問の録音 | 「0.5倍」が明瞭に聞こえた。 |
| 第3問の録音 | 「氷」が明瞭に聞こえた。 |

**判断：** 対象iPadのSafariで、先行検証の最小フロー（読み上げ → 録音 → 自動進行）が3問成立した。回答処理は現段階では録音の取得と再生確認のみで、認識・正誤判定まで成立したという意味ではない。

**注意点：** 読み上げが動かなかった原因が、マイク許可を待つことでユーザー操作に伴う音声開始条件が失われたためかは、処理順序の修正で改善したことからの推測であり、確定していない。今回の録音時間は固定5秒。今後は、文字起こし・確認・採点、録音終了条件、別端末、画面ロック時の挙動を順に検証する。

## 月間運用費の試算

2026年11月17日までの検討時点の概算。家族利用、月2万HTTPリクエスト、AI採点300〜1,000回、1米ドル150円を仮定する。

| 費目 | 月額の目安 | 条件 |
|---|---:|---|
| AWS | 約1〜2米ドル | HTTPS入口、Lambda、Cognito、DynamoDB、バックアップ、シークレット、イメージ保管、ログを含む少量利用の予算。対象の無料枠を想定。 |
| OpenAIのAI採点 | 0.63〜2.10米ドル | GPT-5.4 miniで1回あたり入力1,000・出力300トークン。決まった答えをPythonで照合する問題はAI採点回数に含めない。 |
| AWSとAI採点の基準予算 | 約250〜650円 | AWSの標準HTTPS URLを使う。税と独自ドメインは別。 |
| OpenAIの文字起こし | 送信100分あたり約68円 | gpt-transcribeを1分0.0045米ドルで試算。練習時間全体のうち実際に送った録音分を計上する。 |
| 英語の発音評価 | 未見積もり | サービスの採用と録音時間を決めた後に追加する。 |

たとえば録音を月100分送るなら、**AWS・AI採点・文字起こしの合計は約320〜720円／月**。発音評価の利用料はこの例に含めていない。

- [GPT-5.4 miniの単価](https://developers.openai.com/api/docs/models/gpt-5.4-mini)・[gpt-transcribeの単価](https://developers.openai.com/api/docs/models/gpt-transcribe)

## 初回構築の工数

AWS経験者1人がサンプル教材で初版を動かす場合の基準見積もり。実働 **35〜56時間**、1日8時間で **約5〜7日**。

| 作業 | 目安 |
|---|---:|
| 音声の先行確認 | 4〜7時間 |
| AWSの足回り・初回デプロイ | 7〜11時間 |
| 一問一答・採点・履歴共有 | 9〜14時間 |
| AI採点と検証用答案の確認 | 7〜12時間 |
| 音声の組み込みとPC・スマホの通し確認 | 8〜12時間 |

この工数は、前回のブラウザ音声認識を使う想定で立てた基準値。OpenAIに送る録音処理の追加工数と、発音評価の本実装は実機検証後に見積もり直す。既存Excel教材の一括取り込み、専用の手書き欄、画面ロック中の連続動作も別見積もりとする。
